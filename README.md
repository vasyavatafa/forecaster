# nowcast

Заполняет лаг поставки данных: для каждого недельного ряда `x_t` строит
прогноз `hat_x_t`, используя только `x_{t-1}, x_{t-2}, ...`, чтобы кормить
эти прогнозы в решающее правило `f(hat_x1_t,...,hat_xn_t) ~ y_t`.

## Установка

```bash
python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt
```

## Быстрый старт

```python
from nowcast.pipeline import NowcastPipeline

pipe = NowcastPipeline(
    path="data/weekly.xlsx",
    date_col="date",
    columns=None,                # None -> все нечисловые кроме date_col пропускаются, берутся все value-колонки
    method="bayesian_ar",
    start_train="2022-01-20",
    end_train=None,
)

table = pipe.run_all_methods()          # train/test метрики по всем 5 методам x всем колонкам
wide  = pipe.forecast_table(             # тот же df, что на входе, + по колонке "{x_i}_{method}_frcst"
    list_features=["gdp_proxy", "inflation_proxy"],
    list_methods=["bayesian_ar", "var_multivariate"],
)
est   = pipe.estimate_all_methods()     # оценка времени полного grid search по умолчанию
out   = pipe.search_all_methods(top_k=10, n_jobs=1, save_dir="results")
```

Запусти `python3 examples/run_demo.py` для полного прогона на синтетических данных.

## Логирование (`nowcast/logging_utils.py`)

Каждый `run()`/`forecast_table()`/`grid_search()` показывает tqdm-прогресс
("на какой ты стадии") на двух уровнях: снаружи -- по колонкам/методам,
внутри -- по шагам walk-forward цикла. По завершении стадии (один
метод x одна колонка) печатается зелёная строка `[OK] ... n_train=... test_rmse=...`.
Если на КОНКРЕТНОМ шаге метод падает с исключением (например статистике
не хватило данных, или сингулярная матрица), это ловится, шаг
записывается как NaN, печатается жёлтый `[WARN] ... <дата>: <ошибка>`
(не более 3 подряд, дальше -- одна сводная строка, чтобы не заспамить
вывод), и цикл идёт дальше. Если у метода на конкретной колонке падает
уже **вообще всё** (например явно битый конфиг: неверный `trend`, отрицательные
`lags` и т.п.), стадия целиком помечается красным `[FAIL] ...` и пайплайн
переходит к следующей колонке/фиче, не останавливая весь прогон. Это же
поведение работает и внутри `grid_search`/`search_all_methods` -- один
плохой конфиг не убивает весь перебор.

`show_progress=False` в `run()`/`run_all_methods()`/`forecast_table()`/
`grid_search()` отключает tqdm-бары и `[OK]`-строки (полезно для больших
grid search, где сотни `[OK]` были бы просто шумом), но `[WARN]`/`[FAIL]`
печатаются всегда -- ошибки не прячутся.

## 5 методов (`nowcast/methods.py`, `nowcast/nn_method.py`)

| ключ | что делает | почему так |
|---|---|---|
| `rolling_mean` | среднее в окне `window` | простейший бенчмарк |
| `linear_trend` | OLS/Theil-Sen тренд в окне, экстраполяция на 1 шаг вперёд по реальному недельному смещению (не по индексу после dropna) | корректно учитывает пропуски внутри окна |
| `var_multivariate` | `statsmodels.tsa.api.VAR` (при `q=0`, быстрый OLS-по-уравнениям) либо `VARMAX` (при `q>0`, MLE) на выбранных колонках совместно, с опциональным дифференцированием `d` ("VARIMA") | учитывает кросс-корреляцию рядов; колонки без достаточной истории на данном шаге динамически исключаются из совместной модели |
| `bayesian_ar` | `sklearn.BayesianRidge` на лагах `lags` (+ линейный тренд) | короткие/шумные окна недельных данных легко переобучают обычный OLS AR(p); байесовская регуляризация (evidence maximization) сама подбирает силу шринкейджа коэффициентов в зависимости от того, сколько сигнала реально есть в окне, плюс даёт `step_with_std()` — предиктивную дисперсию для последующего взвешивания `hat_x_t` |
| `nn_revin` | MLP на сыром окне (после RevIN, Kim et al. 2021) + компактных скользящих статистиках (mean/std/min/max/trend/autocorr) по всем колонкам, прогноз всех колонок сразу | RevIN нормализует каждое окно инстанс-вайз (mean/std по самому окну) перед сетью и денормализует прогноз на выходе — устойчиво к нестационарности/сдвигам уровня между эпизодами. Полный refit "с нуля" на каждом шаге бэктеста нереалистично медленный для NN, поэтому по умолчанию используется warm-start: полное обучение на первом шаге, затем `epochs_refit` дообучение на новых данных каждый следующий шаг (`full_retrain=True` — честный refit с нуля на каждом шаге, кратно медленнее) |

Данные передаются каждому методу как проекция на скользящее окно с короткими
внутренними пропусками, заполненными линейной интерполяцией (`interp_limit`
недель) — веса/лаги считаются по реальному календарному расстоянию, а не по
сжатому после `dropna()` индексу.

## Протокол бэктеста (`nowcast/backtest.py`)

Один и тот же walk-forward цикл с рефитом на каждом шаге: модель видит всю
историю слева, прогнозирует ровно одну точку справа, эта точка добавляется в
историю, рефит повторяется. train/test — это не два отдельных прогона, а
две части одного и того же ряда `hat_x_t`, разрезанные по границе 70%
(`cutoff_frac`) **активного диапазона именно этой колонки** (от её первого до
последнего наблюдения) — так колонка, стартующая в 2023, получает свой
собственный 70/30 сплит внутри своей истории, а не глобальный по файлу.
Для мультивариатных методов (`var_multivariate`, `nn_revin`) прогнозы всех
колонок считаются одним общим циклом, а cutoff для метрик применяется к
каждой колонке отдельно.

## Метрики (`nowcast/metrics.py`)

`rmse`, `mae`, `smape`, `r2` — как просили, плюс:
- `mase` — MASE относительно наивного прогноза "значение неделю назад";
  <1 значит модель бьёт наивный бенчмарк. Стандартная для сравнения между
  рядами с разным масштабом метрика, что здесь важно (6+ разных единиц измерения).
- `directional_accuracy` — доля шагов, где знак предсказанного изменения
  совпал с реальным. Для последующей идентификации событий (`y_t in {0,1}`)
  направление движения часто важнее точной величины.

⚠️ `smape` может давать зашкаливающие значения (~90%+) на рядах, часто
переходящих через ноль (в синтетике — `credit_spread`), это артефакт метрики,
а не признак плохого прогноза — смотри `rmse`/`r2`/`mase` рядом.

## Grid search и топ-10 (`nowcast/search.py`)

```python
pipe.estimate_runtime("nn_revin", param_grid={...})   # засекает 2-3 случайные конфигурации, экстраполирует на всю сетку
pipe.grid_search("rolling_mean", param_grid={...}, top_k=10, n_jobs=4)
pipe.search_all_methods(top_k=10, n_jobs=4, save_dir="results")  # все 5 методов сразу + CSV
```

Для унивариатных методов (`rolling_mean`, `linear_trend`, `bayesian_ar`)
топ-10 считается **отдельно по каждой колонке** (`{column: DataFrame}`).
Для мультивариатных (`var_multivariate`, `nn_revin`) конфигурация одна на
все колонки сразу, топ-10 ранжируется по среднему `test_rmse` по колонкам
(`rank_metric` настраивается, по умолчанию `test_rmse`, меньше -- лучше).

На синтетике (330 недель, 6 колонок, дефолтные сетки, top_k=10, n_jobs=1)
полный перебор по всем 5 методам занял **~60 секунд**, оценка `estimate_all_methods()`
заранее дала ~78 секунд — то есть оценке можно доверять с точностью до
множителя ~1.3x на этих объёмах данных.

## Синтетические данные (`synthetic.py`)

`generate_synthetic_dataset()` строит 6 рядов на 5 латентных факторах разной
формы (разные лаги/веса на серию => реальная и структурно разнородная
кросс-корреляция для VAR/NN):

| фактор | процесс | серия |
|---|---|---|
| `f1` | AR(1) | `gdp_proxy` |
| `f2` | AR(2) + линейный тренд `0.01*t` | `inflation_proxy` |
| `f3` | AR(2) + удвоенная волатильность инноваций | `rates_proxy` |
| `f4` | AR(3) + квадратичный тренд `0.00004*t^2` | `consumer_sentiment` |
| `f5` | AR(1) + `0.02*sin(t)` | `credit_spread` |
| `0.6*f1+0.4*f3` | смесь двух факторов | `new_activity_index` |

Недельный шаг с 2020-01-06, старты `consumer_sentiment`/`credit_spread`/
`new_activity_index` в 2022/2023/2024 соответственно, точечные пропуски
(~2%) + один блочный аутэдж, и 3 шоковых эпизода (2020-03, 2022-09,
2024-11: скачок уровня + всплеск дисперсии одновременно во всех рядах).

## Структура

```
nowcast/
  data.py       загрузка xlsx, учёт покрытия по колонкам (first/last valid, пропуски)
  methods.py    методы 1-4 (rolling_mean, linear_trend, var_multivariate, bayesian_ar)
  nn_method.py  метод 5 (nn_revin) + RevIN
  metrics.py    rmse/mae/smape/r2/mase/directional_accuracy
  backtest.py   walk-forward движок с рефитом на каждом шаге + train/test сплит
  search.py     grid search, оценка времени, топ-10
  pipeline.py   NowcastPipeline -- основной класс
synthetic.py    генератор синтетических данных для тестов
examples/run_demo.py  полный прогон на синтетике
```
